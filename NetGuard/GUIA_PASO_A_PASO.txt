NETGUARD — GUÍA DE EJECUCIÓN Y DEFENSA EN VISUAL STUDIO CODE
============================================================
Versión integrada: compilador Python + máquina virtual + backend ASM x86-64.
Representación intermedia elegida: CUÁDRUPLAS EXCLUSIVAMENTE.

1. ABRIR EL PROYECTO
--------------------
En Visual Studio Code selecciona File > Open Folder y abre la carpeta
NetGuard (la que contiene netguard.py). Después abre Terminal > New Terminal.
No escribas el prompt PS C:\...>; ese texto lo muestra PowerShell.

Verifica:
    py --version
    dir

Debes ver netguard.py, pruebas.py, compilador, ply, ejemplos, tests y nativo.
Si el comando py no existe, intenta python --version y usa python en los
comandos siguientes.

2. PRUEBAS AUTOMÁTICAS EN WINDOWS
--------------------------------
Ejecuta, una por una:
    py pruebas.py
    py pruebas_rubrica.py
    py pruebas_final.py --sin-asm

La suite base debe indicar 41 de 41. La suite adicional de rúbrica prueba
casts, WHILE, notación prefija/postfija, generación de ASM y algoritmos; las
pruebas que ensamblan ejecutables se omiten en Windows sin WSL. La suite final
con --sin-asm valida el intérprete Python sin intentar GCC/Linux.

En Linux/WSL, con GCC instalado, ejecuta sin --sin-asm:
    python3 pruebas.py
    python3 pruebas_rubrica.py
    python3 pruebas_final.py

4. GENERACIÓN DE ENSAMBLADOR Y EJECUCIÓN NATIVA
------------------------------------------------
Se puede generar el archivo .asm desde Windows:
    py netguard.py tests/execution/factorial.ng --asm factorial.asm --no-ejecutar

El ASM generado usa GNU as, sintaxis Intel, ABI System V y destino Linux
x86-64. No es un .exe de Windows. Para ensamblar, enlazar y ejecutar se
requiere Linux x86-64 o WSL Ubuntu con Bash y GCC.

Desde la terminal WSL, cambia a la ruta equivalente del disco Windows. Por
ejemplo, D:\Proyectos\NetGuard normalmente se ve como /mnt/d/Proyectos/NetGuard:
    cd /mnt/d/Proyectos/NetGuard
    bash nativo/compilar_linux.sh factorial.asm nativo/factorial_nativo
    ./nativo/factorial_nativo

En Ubuntu, si GCC no está instalado:
    sudo apt update
    sudo apt install -y gcc

5. CÓMO EXPLICAR LAS TRES CAPAS
--------------------------------
FRONT-END:
  lexer.py     Convierte texto fuente en tokens.
  parser.py    Reconoce la gramática y ejecuta acciones semánticas dirigidas
               por sintaxis.
  semantic.py  Verifica tipos, administra pilas semánticas y árboles.
  symtable.py  Administra símbolos, ámbitos y direcciones virtuales.

MIDDLE-END:
  codegen.py   Genera las cuádruplas, enumera instrucciones y aplica
               backpatching para completar destinos de saltos.
  optimizer.py Optimiza cuádruplas y registra los cambios en una bitácora.

BACK-END:
  vm.py            Interpreta cuádruplas en Python.
  register_alloc.py Describe la asignación local de registros físicos.
  asm_codegen.py   Traduce cuádruplas optimizadas a ASM x86-64 Linux.
  nativo/runtime.c Resuelve entrada/salida de logs, eventos y estructuras.

netguard.py coordina la CLI y las fases; errors.py centraliza los códigos de
error; ply/ contiene la biblioteca usada para lexer y parser.

6. EJEMPLO PRINCIPAL: reglas.ng
--------------------------------
LIMIT maxAttempts : int = 5
LIMIT trafficLimit : float = 500.0
LOAD EVENTS FROM "red_laboratorio.log" AS traffic
FOR EACH event IN traffic
    LET suspicious : boolean = false
    IF event.failedAttempts >= maxAttempts OR event.trafficMB > trafficLimit
        suspicious = true
        ALERT "Evento sospechoso" FROM event.sourceIP
    ELSE
        MARK event AS "normal"
    END
END

Interpretación: por cada evento, se comparan intentos fallidos y tráfico.
Si al menos una condición se cumple se genera ALERT; de lo contrario MARK.

9. LIMITACIONES QUE DEBEN EXPLICARSE CON HONESTIDAD
---------------------------------------------------
  * NetGuard procesa archivos LOG guardados; no captura tráfico en vivo.
  * El backend nativo es GNU as/Intel para Linux x86-64; Windows requiere WSL.
  * El asignador de registros es local por instrucción, no global por vida útil.
  * La optimización de invariantes de ciclos está acotada a patrones FOR EACH.
  * Los benchmarks miden tiempo de pared y asignaciones de memoria Python;
    el perfil nativo es estático y no mide RSS real ni ciclos de CPU.
  * Las funciones admiten hasta seis parámetros; STRUCT usa campos básicos.
